# Resilient Telemetry for Lunar Exploration Infrastructure

Academic project developed for the **Computing Systems and Infrastructure** course, as part of the Bachelor's Degree in Data Engineering and Data Science.

This project implements a containerized telemetry pipeline that simulates data transmission between a Lunar Surface Rover and a Gateway Orbiter. The system uses Python-based telemetry producers, Apache Kafka, Telegraf and InfluxDB to collect, process, store and visualize mission data in near real time.

## Overview

The project simulates a resilient data ingestion architecture for lunar exploration infrastructure, where telemetry generated by different rover subsystems is transmitted through a message broker and persisted in a time-series database.

The pipeline follows this architecture:

```text
Python Producers → Kafka → Telegraf → InfluxDB → Dashboard & Alerts
```

The system was designed to reflect challenges common in space communication scenarios, such as intermittent connectivity, burst data transmission and the need for reliable telemetry monitoring.

## Main Features

* Containerized architecture using Docker Compose
* Apache Kafka deployed in KRaft mode
* Three Python telemetry producers simulating rover subsystems
* Telegraf ingestion agent consuming Kafka topics
* InfluxDB time-series database for telemetry storage
* Mission Control dashboard exported as JSON
* Flux alert scripts for anomaly detection
* Network separation between telemetry generation and ground-control storage
* Persistent volumes for Kafka and InfluxDB

## System Architecture

The architecture is composed of two isolated Docker networks:

* `deep-space-net` — connects the telemetry producers to Kafka
* `ground-control-net` — connects Telegraf to InfluxDB

Kafka and Telegraf act as bridge services between the simulated rover telemetry layer and the ground-control monitoring layer.

## Telemetry Producers

The project includes three Python producers, each simulating a different subsystem.

### Producer A — Rover Mobility & Power Unit

File:

```text
producers/producer_mobility.py
```

Kafka topic:

```text
telemetry-mobility
```

Simulated metrics:

* battery voltage
* motor RPM
* wheel traction

The producer simulates cyclic battery discharge/recharge and random traction drops to represent regolith slippage.

### Producer B — Environmental & Life Support System

File:

```text
producers/producer_eclss.py
```

Kafka topic:

```text
telemetry-eclss
```

Simulated metrics:

* external temperature
* radiation level
* internal cabin pressure

The producer simulates varying lunar environmental conditions and different radiation levels.

### Producer C — High-Gain Antenna Diagnostics

File:

```text
producers/producer_hga.py
```

Kafka topic:

```text
telemetry-comms
```

Simulated metrics:

* signal-to-noise ratio
* bit error rate
* latency

The producer simulates communication quality degradation through changing SNR, BER and latency values.

## Data Flow

1. Python producers generate telemetry data.
2. Data is serialized using the InfluxDB Line Protocol.
3. Messages are sent to Kafka topics.
4. Telegraf consumes messages from Kafka.
5. Telegraf writes the telemetry data to InfluxDB.
6. InfluxDB stores the data in the `lunar-mission` bucket.
7. Dashboards and Flux alerts are used to monitor the mission data.

## Alerts

The project includes Flux alert scripts for each telemetry subsystem:

```text
flux/alert_mobility.flux
flux/alert_eclss.flux
flux/alert_hga.flux
```

Alert examples:

* low battery voltage
* high radiation levels
* degraded communication signal quality

Each alert defines OK, INFO, WARN and CRIT thresholds according to the monitored metric.

## Dashboard

The Mission Control dashboard is exported in:

```text
dashboard/lunar_mission_dashboard.json
```

The dashboard is designed to support near real-time monitoring of lunar telemetry metrics, including mobility, power, environmental conditions, life support and communications.

## Configuration

Create a `.env` file locally based on `.env.example`.

Example:

```text
DOCKER_INFLUXDB_INIT_USERNAME=your_username
DOCKER_INFLUXDB_INIT_PASSWORD=your_password
DOCKER_INFLUXDB_INIT_ORG=esa-sic
DOCKER_INFLUXDB_INIT_BUCKET=lunar-mission
DOCKER_INFLUXDB_INIT_ADMIN_TOKEN=your_admin_token
```

The `.env` file should never be committed to the public repository.

## How to Run

### 1. Clone the repository

```bash
git clone https://github.com/catarinarabuge/resilient-telemetry-lunar-exploration.git
cd resilient-telemetry-lunar-exploration
```

### 2. Create the environment file

Create a `.env` file from `.env.example` and fill in the required values.

### 3. Start the system

```bash
docker compose up --build
```

This command starts:

* Kafka
* InfluxDB
* Telegraf
* Mobility producer
* ECLSS producer
* HGA producer

### 4. Access InfluxDB

Open:

```text
http://localhost:8086
```

Use the credentials defined in the local `.env` file.
